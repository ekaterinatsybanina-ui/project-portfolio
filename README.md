# Портфель-панель

Учебный проект: приложение для мониторинга портфеля проектов университетского отдела, который реализует проекты в сфере **образования, науки и технологического предпринимательства**.

> ⚠️ Все данные в приложении **синтетические** (вымышленные). Сведения о реальном отделе в проекте не используются; описание его процессов в `docs/business_statement.md` помечено как гипотезы, которые нужно подтвердить интервью.

## Проблема
Статусы проектов собираются вручную из разных таблиц и чатов, поэтому нет единой актуальной картины: риски срыва сроков и перерасхода видны поздно, нагрузка сотрудников по нескольким проектам не считается, отчёт для руководства готовится вручную.

## Решение
Локальное веб-приложение: план и факт по срокам и бюджету, автоматический балл риска (0–100) с причинами, загрузка сотрудников, еженедельный отчёт в Excel и Markdown, оценка экономии времени.

## Возможности
- Дашборд с KPI и списком проектов, требующих внимания
- Список проектов с фильтрами, добавление проекта, обновление статуса, контрольные точки
- Загрузка сотрудников (перегрузка и недогрузка)
- Отчёт: просмотр и скачивание (Markdown, Excel)
- Калькулятор эффекта: все исходные числа вводит пользователь
- Проверка ввода (даты, отрицательные значения, прогресс 0–100%)

## Технологии
Python 3.10+, Streamlit, pandas, SQLite (стандартная библиотека), openpyxl, pytest. Всё бесплатное, платных API нет.

## Запуск
```bash
python -m venv .venv
# Windows: .venv\Scripts\activate     macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```
Приложение откроется в браузере. При первом запуске база `data/portfolio.db` создаётся и заполняется демо-данными (кнопка «Пересоздать демо-данные» в боковой панели).

## Тесты
```bash
pytest
```

## Структура
```
app.py              интерфейс Streamlit
src/logic.py        расчёт риска, нагрузки, KPI, проверки, отчёт (без Streamlit и БД)
src/db.py           SQLite: схема и операции
src/demo_data.py    синтетические данные
tests/test_logic.py автотесты
docs/business_statement.md  бизнес-постановка
```

## Как считается риск
Баллы суммируются (максимум 100): жёлтый ≥ 25, красный ≥ 50. Пороги — константы в начале `src/logic.py`.

| Условие | Баллы |
|---|---|
| Отставание фактического прогресса от планового ≥ 15 / ≥ 30 п.п. | +20 / +40 |
| Доля израсходованного бюджета опережает прогресс на ≥ 10 / ≥ 20 п.п. | +15 / +30 |
| Каждая просроченная контрольная точка | +15 (максимум +30) |
| Плановая дата окончания прошла, проект не завершён | +30 |
| Статус не обновлялся > 14 / > 30 дней | +10 / +20 |

Плановый прогресс = доля прошедшего времени между датой начала и окончания. Риск считается для проектов в статусах «В работе» и «Приостановлен».
